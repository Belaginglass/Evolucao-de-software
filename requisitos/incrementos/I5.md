# Incremento 5 — Gerenciamento de privilégios dos atores

**Caso de uso:** UC004 — Manter Privilégio dos Atores

> Fonte: *Requisitos_e_Casos_de_Uso.pdf*, seção 6, p. 31-33.

## UC004 — Manter Privilégio dos Atores

**Descrição:** o sistema deve oferecer um meio do Diretor Geral `[ATR-1]` adicionar e remover privilégios de outros atores, por meio de uma lista de atores já cadastrados, com possibilidade de busca e filtro por privilégio.

**Atores:** Diretor Geral `[ATR-1]`.

**Precondições:** Estar autenticado no sistema e ser autorizado a realizar essa atividade.

**Pós-condições:** Alteração nos privilégios dos usuários já cadastrados no sistema.

### Fluxo Básico
1. Diretor Geral acessa "Gerenciar usuários" no menu administrativo.
2. Sistema retorna `[PRT-10]`.
3. Ator habilita/desabilita níveis de acesso dos usuários listados. Se marcar filtro → `[FA-9]`; se clicar "cancelar" → `[FA-3]` (UC002); se clicar "Desabilitar/Habilitar" nas colunas "Diretor geral" ou "Gestor de adoção" → segue o fluxo básico.
4. Sistema cria uma tabela acima da lista principal com os usuários alterados pelo ator.
5. Ator clica em "salvar".
6. Sistema salva a nova atribuição de privilégios, retorna a `[PRT-2]` com mensagem de sucesso e segue as diretrizes de gerência de agenda da `<RN009>`.

### Fluxo Alternativo — `[FA-9]` Filtros
1. Inicia ao preencher o campo de busca por nome ou marcar filtro por cargo em `[PRT-10]`.
2. Sistema exibe os usuários correspondentes ao nome ou cargo filtrado.
3. Ao clicar "limpar filtro", sistema retorna à ordem alfabética natural, sem filtros.

### Protótipos referenciados
`[PRT-10]` Manter Atores.

## Requisito Funcional relacionado

**`<RF006>` Manter privilégio dos atores**
> "O sistema deve exibir todos os usuários administrativos do sistema e disponibilizar meios para alterar seus privilégios aumentando, habilitando ou desabilitando o acesso administrativo temporariamente ou excluindo permanentemente o acesso administrativo. Deve haver filtros para facilitar a busca pelos usuários."

## Requisito Não Funcional relacionado

**`<RNF005>` Alterar estados** *(transversal — ver `requisitos_transversais.md`)*
> "Deverá ser usado o padrão de projeto state para realizar as funções de alteração de estado existentes no sistema, tais como mudança de estado da adoção, processo de aceite de um novo usuário administrativo entre outros."

## Regra de Negócio relacionada

**`<RN009>` Gerência de agendas** *(transversal — citada também nos Incrementos 7 e 9; ver `requisitos_transversais.md`)*
> "O sistema deverá usar um endereço de e-mail para usar o serviço de agenda para prestação de serviços, visitas ao animal durante o processo de adoção e dias de eventos. [...] Deverá haver também uma agenda para cada Gestor de adoção e Diretor geral [...]. Quando um usuário virar gestor de adoção ou diretor geral o sistema deverá criar uma agenda com seu nome, salvar o identificador dessa agenda em suas informações no banco de dados e utilizar seu endereço de e-mail salvo durante seu cadastro para compartilhar esta agenda com este usuário. [...] Sempre que houver criação de eventos na agenda o sistema deverá enviar e-mails para confirmar a participação das pessoas envolvidas."
