# Incremento 10 — Gerenciamento de eventos, doações e relatórios

**Casos de uso:** UC012 (Manter eventos), UC013 (Manter doações) e UC014 (Manter relatórios)

> Fonte: *Requisitos_e_Casos_de_Uso.pdf*, seção 6, p. 77-87.

## UC012 — Manter eventos

**Descrição:** o sistema deve prover um mecanismo para criação, edição e deleção de eventos.

**Atores:** Diretor geral.

**Precondições:** Estar autenticado e autorizado.

**Pós-condições:** Criação, edição ou deleção de um evento.

### Fluxo Básico
1. Diretor geral acessa "eventos" no menu público.
2. Sistema retorna `[PRT-45]`, incluindo opção de adicionar fotos a eventos ocorridos/em andamento; na visualização pública, inclui botão "saiba mais" nesses eventos.
3. Se clicar "x" em um evento, sistema confirma a exclusão; se confirmado, exclui. Se clicar "editar", abre modal de edição. Se clicar "adicionar fotos", abre modal para envio/incorporação de fotos com legenda. Se clicar "criar evento" → segue o fluxo básico.
4. Sistema abre modal para criação de evento; a visão pública é reordenada pela data mais próxima (`[PRT-46]`); a criação de evento também sumariza os eventos mensais para os voluntários, conforme `<RN013>`.
5. Se clicar "saiba mais" → sistema retorna `[PRT-47]`.
6. Se clicar nas "setas", sistema passa as fotos anexadas; se clicar "x" → `[FA-3]` (UC002); se clicar "próximo evento", recarrega com o próximo evento da listagem.

### Protótipos referenciados
`[PRT-45]` Página de eventos (administrativa) · `[PRT-46]` Página pública de eventos · `[PRT-47]` Visualização de evento.

*(Não há fluxos alternativo/exceção descritos para este UC no documento original.)*

## UC013 — Manter doações

**Descrição:** o sistema deve possuir um modo de manter pedidos de doação.

**Atores:** Diretor geral.

**Precondições:** Estar autenticado e autorizado.

**Pós-condições:** Criar, editar ou excluir um pedido de doação.

### Fluxo Básico
1. Gestor acessa a página de doações pelo menu principal.
2. Sistema retorna `[PRT-48]`.
3. Se clicar "x" em um pedido, sistema confirma a exclusão; se confirmado, exclui. Se clicar "editar", abre modal de edição. Se clicar "adicionar fotos", abre modal de envio/incorporação de fotos com legenda (com opção de deletar fotos já enviadas). Se clicar "criar pedido" → segue o fluxo básico.
4. Sistema abre modal para criação de pedido; a visão pública é reordenada pela data mais próxima (`[PRT-49]`); a criação também sumariza os pedidos existentes e informa os voluntários, conforme `<RN013>`.
5. Se clicar "veja doações já obtidas" → sistema retorna `[PRT-50]`.
6. Se clicar nas "setas", sistema passa as fotos anexadas; se clicar "x" → `[FA-3]` (UC002); se clicar "próxima campanha", exibe a próxima campanha da listagem.

### Protótipos referenciados
`[PRT-48]` Página de doações (administrativa) · `[PRT-49]` Doações (visualização pública) · `[PRT-50]` Doações já realizadas.

*(Não há fluxos alternativo/exceção descritos para este UC no documento original.)*

## UC014 — Manter relatórios

**Descrição:** o sistema deverá prover uma página com relatórios.

**Atores:** Diretor geral e gestor de adoção.

**Precondições:** Estar autenticado e autorizado.

**Pós-condições:** Não há (conforme o documento original).

### Fluxo Básico
1. Ator clica na guia "relatórios" no menu administrativo.
2. Sistema retorna `[PRT-51]`, contendo dados interessantes para os gestores.

### Protótipos referenciados
`[PRT-51]` Tela de relatórios.

*(Não há fluxos alternativo/exceção descritos para este UC no documento original; o documento também não detalha quais relatórios específicos devem existir.)*

## Requisito Funcional relacionado

**`<RF013>` Doações** (UC013)
> "O sistema deve disponibilizar a funcionalidade de gerar doações monetárias a ONG. Essa doação pode ser através do boleto ou similar. Essa funcionalidade deve ser pública, não necessitando de cadastro para realizá-la, mas caso o usuário estiver autenticado os dados que forem possíveis devem ser reaproveitados."

*(UC012 "Manter eventos" e UC014 "Manter relatórios" não correspondem a nenhum `<RFxxx>` numerado na seção 4; decorrem dos requisitos de usuário da seção 2.2: "[ATR-01] Manter eventos" e "[ATR-01]/[ATR-02] Manter relatórios".)*

## Requisito Não Funcional relacionado

**`<RNF007>` Sumarização de doações e feedback** *(transversal — aplica-se aqui à sumarização de pedidos de doação; ver também Incremento 8 e `requisitos_transversais.md`)*
> "O sistema deverá sumarizar os pedidos de doação e mensagens de feedback para o gestor de adoção. [...]"

## Regra de Negócio relacionada

**`<RN013>` Notificações de eventos e doações**
> "O sistema deve notificar a todos os usuários que sejam voluntários sobre os eventos e pedidos de doação que sejam criados no sistema. Esta notificação deve ser feita via sistema e via e-mail. A notificação via e-mail deve ser mensal e deve sumarizar todos os eventos do mês e todos os pedidos de doação criados e que ainda estejam ativos no sistema."
