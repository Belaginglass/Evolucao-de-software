# Incremento 2 — Cadastro e manutenção de usuários

**Casos de uso:** UC002 (Cadastro) e UC011 (Manter cadastro)

> Fonte: *Requisitos_e_Casos_de_Uso.pdf*, seção 6, p. 24-26 (UC002) e p. 75-77 (UC011).

## UC002 — Cadastro

**Descrição:** o sistema deve possuir um meio de cadastro de usuário. O cadastro exige as informações descritas em `<RN002>`.

**Atores:** Não se aplica.

**Precondições:** Não estar autenticado.

**Pós-condições:** Ao final, um novo usuário deverá estar cadastrado no banco de dados.

### Fluxo Básico
1. Ator clica em "Cadastre-se aqui" em `[PRT-1]`.
2. Sistema retorna `[PRT-6]`.
3. Ator preenche os campos do formulário.
4. Se clicar "Adicione outro" → `[FA-4]`; se clicar "Cancelar" → `[FA-3]`; segue o fluxo básico se clicar "Cadastrar".
5. Sistema valida as informações conforme `<RN002>`; se inválidas → `[FE-1]` (do UC001); se válidas, gera uma miniatura (thumbnail) da imagem enviada, cadastra os dados, informa sucesso, inicia a sessão do ator e o direciona para `[PRT-3]`.

### Fluxo Alternativo — `[FA-3]` Cancelar
1. Inicia quando o ator clica em "Cancelar" ou no "x".
2. Sistema retorna para a página anterior.

### Fluxo Alternativo — `[FA-4]` Adicionar campo telefone ou endereço
1. Inicia quando o ator clica em "Adicionar outro" próximo aos campos de telefone ou endereço.
2. Sistema replica os campos para mais um telefone ou endereço; o fluxo básico continua.

### Protótipos referenciados
`[PRT-6]` Cadastro de usuário.

## UC011 — Manter cadastro

**Descrição:** o sistema deve prover um mecanismo para o ator atualizar seus próprios dados cadastrais.

**Atores:** Não se aplica.

**Precondições:** Estar autenticado.

**Pós-condições:** Atualizar as informações pessoais no banco de dados.

### Fluxo Básico
1. Ator clica em "meus dados" no menu.
2. Sistema retorna `[PRT-44]`.
3. Ator preenche os novos dados pessoais; se clicar "cancelar" → `[FA-3]` (do UC002); se clicar "salvar" → segue o fluxo básico.
4. Sistema segue as especificações de `<RN011>` e retorna mensagem de sucesso.
5. Se o ator acessar seu e-mail e abrir o link enviado → `[FA-21]`.

### Fluxo Alternativo — `[FA-21]` Recuperação dos dados pessoais
1. Inicia quando o ator acessa o link enviado por e-mail (conforme `<RN011>`).
2. Sistema direciona o ator para `[PRT-44]`.
3. Ator preenche nova senha e demais dados pessoais, se necessário.
4. Sistema valida e salva a alteração, seguindo novamente as recomendações de `<RN011>` para mudança de senha.

### Protótipos referenciados
`[PRT-44]` Alteração de dados pessoais.

## Requisito Funcional relacionado

**`<RF010>` Manter cadastro**
> "O sistema deverá oferecer um meio de alterar seus dados cadastrais de qualquer usuário."

*(UC002 — cadastro inicial — não corresponde a nenhum RF numerado específico no documento original; a necessidade decorre do requisito de usuário listado na seção 2.2: "[ATR-03] Manter cadastro".)*

## Requisitos Não Funcionais relacionados

**`<RNF002>` Busca de CEP**
> "O sistema deve buscar pelo CEP as informações referentes à Rua, Bairro, Cidade e Estado, facilitando assim o preenchimento do formulário. Isto ocorre nos cadastros especificados no UC02 e UC04. Esta busca pode ser realizada utilizando API's como Postmon e similares."

**`<RNF001>` Criptografia do sistema** *(transversal — aplica-se à senha criada/alterada neste UC)*
> "Todas as senhas do sistema deverão ser criptografadas com o algoritmo SHA-256 e um salt de 8 bits antes de serem salvas no banco de dados."

## Regras de Negócio relacionadas

**`<RN002>` Informações de cadastro**
> "As seguintes informações são necessárias para o cadastro de pessoa: Nome; E-mail; Senha; CPF; Data de nascimento; Número(s) de telefone (verificar WhatsApp e identificação do número); Endereço (Rua, Número, Complemento, Bairro, Cidade, Estado, CEP); Foto para identificação (JPG, PNG e similares); Deseja ser voluntário? (Sim/Não). Todas as informações são obrigatórias, pelo menos um número de telefone deve ser inserido e a senha deve conter pelo menos oito dígitos. E-mail e CPF devem ser únicos no sistema. O sistema deverá gerar uma miniatura (thumbnail) da imagem enviada e armazená-la."

**`<RN011>` Alteração dos dados pessoais**
> "Durante a alteração dos dados pessoais o sistema deve salvar a data de alteração dos dados, criar um hash utilizando do método randomUUID da classe UUID do pacote util do Java, este hash deverá ser salvo junto ao registro do usuário e enviado como link por e-mail informando da alteração dos seus dados [...]. Caso o usuário utilize o link enviado a ele por e-mail o sistema deverá procurar por todos os registros relacionados a atividades do usuário no sistema desde a data de alteração até a data atual e excluir todos esses registros, o sistema também deve obrigar o usuário a atualizar sua senha e se necessário suas outras informações pessoais."

**`<RN001>` Validação de e-mail e senha** *(transversal — ver Incremento 1 / `requisitos_transversais.md`)*
> Aplica-se à validação dos campos de e-mail e senha preenchidos no cadastro (UC002).

A referência a "UC04" (UC004 — Manter Privilégio dos Atores) é mantida tal como está no texto-fonte, embora os fluxos descritos para UC004 não incluam campos de endereço — possível inconsistência de numeração do documento original, reproduzida sem correção para não inventar conteúdo.
